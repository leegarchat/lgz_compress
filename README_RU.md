# lgz_compress

> Автономный Rust-порт бинарного компрессора `lgz`: ELF-ориентированный препроцессинг (нормализация переходов ARM64/x86, разделение на байтовые плоскости, дельта-кодирование) + LZMA2 с брутфорс-оптимизатором, одиночные архивы и solid-мультиконтейнеры с метаданными и прозрачным инжестом ZIP.

Утилита полностью автономна: чистый безопасный Rust без C-зависимостей, поставляется полностью статическими musl-бинарниками (x86_64, x86, aarch64, armv7). Хостовая сборка умеет паковать (`compress`, `pack`); облегченный decompress-only вариант (`--no-default-features`, он же едет в `target/push/` на устройство) только распаковывает и инспектирует. Пейлоады одиночных архивов (UCOMP01) побайтово совместимы с оригинальной C-утилитой в обе стороны.

## Ключевые возможности

* **100% автономная статика**: никакого C-кода `libc`, никакой liblzma, никаких рантайм-зависимостей. `lzma-rust2` + `rayon` (только хост) + `zip` + биндинги `libc` — всё чистый Rust, musl-статика на 4 архитектуры.
* **ELF-ориентированный препроцессинг**: нормализация переходов ARM64 (`B`/`BL`/`ADRP`) и x86 (`E8`/`E9`, относительные → абсолютные), разделение ARM64-инструкций на байтовые плоскости (stride 4), дельта-кодирование — по исполняемым секциям ELF `PROGBITS`.
* **Брутфорс-оптимизатор**: уровни 0–3 перебирают (препроцессинг × комбинации `lc`/`lp`/`pb`: 1 / 2 / 57 / 225 проходов), мультиблочная и single-blob раскладки конкурируют; побеждает меньший образ, ничьи разрешаются детерминированно (число потоков влияет только на скорость, не на байты).
* **Solid-мультиконтейнеры (UCOMP02)**: много файлов пакуются в один общий LZMA2-поток — пофайловая нормализация, 4-байтовое выравнивание, кластеризация по именам (ARM64-исполняемые → shared-объекты → скрипты → данные), один прогон оптимизатора на весь набор.
* **Сохранение метаданных**: биты прав (октал `755` или символьные `rwxr-xr-x`), владелец (`root:shell` или `0:2000`), SELinux-контексты — по строкам манифеста, `--preserve-*` из файловой системы или принудительные `--chmod/--owner/--context` для всех записей; точечные флаги восстановления (`--no-owner`, `--preserve-perms`, …).
* **Прозрачный инжест ZIP**: `.zip`-записи открываются при упаковке — внутренние файлы (расжатые, legacy-UCOMP-пейлоады декодируются в чистые байты) уходят в общий solid-поток с полным препроцессингом; виртуальное оглавление (методы, права, метки времени, CRC) пересобирает валидный `.zip` при распаковке (`unzip -t` чистый).
* **Инспектор архивов**: `list` печатает выровненную таблицу содержимого + футер (счетчики, размеры, процент) не трогая solid-поток; `extract` вытаскивает одну запись (со структурой, `--flatten` или явным именем файла).
* **Decompress-only вариант**: Cargo-фича `compress` (включена по умолчанию); `--no-default-features` вырезает кодировщик, матчеры и `rayon` — ramdisk-бинарник умеет только `decompress`/`extract`/`list`.
* **Защита от Zip-Slip**: `safe_join` отклоняет абсолютные пути и `..`; каталоги создаются покомпонентно с отказом идти по симлинкам; запись файлов через `O_NOFOLLOW`; симлинки создаются последними. Весь парсинг заголовков/смещений с проверкой границ (`checked_*`, явная валидация диапазонов).
* **Детерминированный выход**: одинаковые входы → побайтово идентичные архивы на любой хост-архитектуре и любом числе потоков (проверено хост vs `qemu-aarch64`).

## Архитектура репозитория

```text
Cargo.toml                  Корень пакета (фичи: default = ["compress"]; [profile.release]: LTO fat, abort, strip)
build.sh                    Статический мультиархитектурный сборщик musl (x86_64/x86/aarch64/armv7) через cargo или cross
dist/                       Предсобранные статические бинарники, полная версия (lgz_compress-linux-*)
target/push/                Push-копии {name}_{arch}, decompress-only версия (adb push на устройство)
src/main.rs                 Диспетчер команд (compress/pack/decompress/list/ls/extract/x/help) + справки
src/compress.rs             Конвейер целого файла: ELF-чанкинг, multi-block vs single-blob брутфорс (rayon)
src/chunk.rs                По-чанковый выбор препроцессинга (типы 0/1/2)
src/decompress.rs           Декод UCOMP01 + инверсия по-типового постпроцессинга
src/pack.rs                 Контейнер UCOMP02: резолв манифеста, раскладка solid, фазы распаковки, пересборка zip
src/inspect.rs              list (только фрейминг) + точечный extract одной записи
src/manifest.rs             Парсер сборочного манифеста (строки file/dir/link/zip)
src/meta.rs                 Парсинг chmod/owner/context, preserve из FS (stat/xattr), фильтрованное применение (chmod/chown/setxattr)
src/elf.rs                  Парсер секций/архитектуры ELF64 с проверкой границ
src/normalize.rs            Нормализация/денормализация переходов ARM64/x86 (точная инволюция)
src/planes.rs               Разделение/сборка байтовых плоскостей ARM64 (stride 4)
src/delta.rs                Дельта-кодирование/декодирование (wrapping-арифметика)
src/lzma.rs                 LZMA2-бэкенд (фрейминг [props][поток], кодек словаря/props, маппинг глубины)
src/format.rs               Фрейминг UCOMP01 (magic, LE-заголовки, таблица чанков + валидация)
```

## Форматы архивов

**UCOMP01** (одиночный байтовый поток, фрейминг совместим с C):

```text
[8] magic "UCOMP01\0" | [8] исходный размер (LE) | [4] число чанков
на чанк: [1] тип препроцессинга | [4] orig размер | [4] comp размер (с байтом props LZMA2) | [N] пейлоад
```

Типы препроцессинга: `0` raw · `1` arm64 planes+delta · `2` delta · `3` нормализация переходов ·
`4` нормализация+planes+delta · `5` дельта файла · `6` нормализация+дельта файла.

**UCOMP02** (мультифайловый solid-контейнер): таблица записей (путь, тип file/dir/link/zip, опциональные
mode/uid/gid/context, диапазоны в solid, диапазоны ELF-кода для денормализации, виртуальное оглавление zip
с методами/правами/временем/CRC) + один solid UCOMP01-блоб + 4-байтовое выравнивание файлов.

**Манифест** (обычный текст, пути относительно CWD):

```text
file <path> [chmod] [owner] [context]
dir  <path> [chmod] [owner] [context]
link <path> -> <target> [chmod] [owner] [context]
zip  <path> [chmod] [owner] [context]
```

(`-` пропускает поле; строка `file`, указывающая на zip-данные, инжестится автоматически.)

## Защитные лимиты целостности

* Заголовки контейнера/чанков полностью проверяются границами; неизвестный magic, неверные счетчики, обрезанные пейлоады, несовпадение суммы размеров → жесткие ошибки, никакого молчаливого повреждения.
* Лимит декодера: 256 МиБ на UCOMP01-пейлоад (как в C); диапазоны solid валидируются до нарезки.
* Входы больше 4 ГиБ отклоняются (C молча обрезал их до 32 бит).
* Применение метаданных — best-effort с предупреждениями (`chown`/`setxattr` без привилегий не роняют прогон); флаги `--no-*` отключают категории целиком (безопасно для FAT32/exFAT).
* Коды выхода: `0` успех, `1` ошибка. Ошибки пробрасываются с контекстом; `main` — единственная точка выхода.

## Сборка и компиляция

**Требования**:
* Тулчейн Rust (stable, edition 2024).
* Менеджер пакетов Cargo.
* Для статических сборок: musl-тулчейны или `cross` (подсказки по установке под каждый дистрибутив — в `build.sh --help`).

```bash
# Быстрая локальная сборка (хостовый таргет)
cargo build --release
# -> target/release/lgz_compress

# Decompress-only вариант (то, что едет на устройство)
cargo build --release --no-default-features

# Статические мультиархитектурные сборки через build.sh (musl, stripped):
#   --cargo | --cross | --auto   метод сборки (auto = cross при наличии контейнеров, иначе cargo)
#   --arch all|x64|x86|arm64|arm32
./build.sh --cargo --arch x64      # x86_64-unknown-linux-musl
./build.sh --cross --arch arm64    # aarch64 через контейнеры
./build.sh --arch all              # x86_64, x86, aarch64, armv7

# Проверки
cargo test                  # полная версия: 5 passed
cargo test --no-default-features   # облегченная версия: 4 passed
```

Выходы сборки:

* `dist/` — статические бинарники `lgz_compress-linux-*`, **полная** версия (compress + pack + unpack).
* `target/push/` — 8 push-копий, обе версии под каждую архитектуру, например:
  `adb push target/push/lgz_compress_lean_arm64 /data/local/` (`dist/` и `target/` в gitignore).

| Arch | `*_full_*` (compress + unpack) | `*_lean_*` (decompress-only) | Экономия |
|---|---|---|---|
| x64 | 1 061 616 | 729 560 | −31% |
| x86 | 993 888 | 698 752 | −30% |
| arm64 | 913 552 | 642 968 | −30% |
| arm32 | 916 184 | 621 060 | −32% |

Lean-вариант (`--no-default-features`) вырезает кодировщик LZMA2, матчеры
и `rayon`; остаются только `decompress`/`extract`/`list`. Остаток (~600 КБ) —
несжимаемое ядро декода: декодер LZMA2, `zip`+inflate, таблицы денормализации
и std. Сознательно отклонено ради скорости распаковки: `opt-level=z`
(−75 КБ, но +11% времени декода) и удаление ASM декодера (−192 Б, ноль эффекта).

## Справочник по интерфейсу CLI

```bash
lgz_compress compress <input> <output> [level] [-l N] [-j N] [meta flags]
lgz_compress pack <manifest> <output> [-l N] [-j N] [meta flags]
lgz_compress decompress <archive> [dest] [--no-owner --no-context ...]
lgz_compress list <archive>                      # алиас: ls
lgz_compress extract <archive> <file> [dest] [--flatten]   # алиас: x
lgz_compress help [command|manifest]
```

Уровни: `0` быстрый (один проход) · `1` баланс · `2` глубокий, по умолчанию (57 проходов) · `3` экстремальный (225 проходов, словарь 64 МиБ на больших входах). `-j/--threads` по умолчанию все ядра (уровень 0 сериален по дизайну).

Управление метаданными при восстановлении (`decompress`, `extract`): по умолчанию
восстанавливается всё сохранённое; `--no-meta` — ничего; `--no-perms/--no-owner/--no-context`
(или `--skip-*`) вычитают категории; `--preserve-perms/--preserve-owner/--preserve-context`
включают по одной (`--preserve-all` = по умолчанию). У `extract` дополнительно
`--flatten` (отбросить пути архива). Полная документация манифеста и флагов: `help manifest`.

```bash
lgz_compress compress app_process64 app.lgz 2
lgz_compress pack tree.txt system.lgz -l 1 --preserve-all
lgz_compress decompress system.lgz /tmp/restore --no-owner --no-context
lgz_compress list system.lgz
lgz_compress extract system.lgz bin/toybox /tmp/out --flatten
```

## Замеры и валидация

Замерено на 16-ядерном x86_64 хосте (плюс контроль декода под `qemu-aarch64`).
Время настенное; `t_enc`/`t_dec` в секундах.

### Одиночные файлы (один бинарь → один UCOMP01)

| Файл (RAW) | L0 размер / enc / dec | L1 размер / enc / dec | L2 размер / enc / dec | L3 размер / enc / dec |
|---|---|---|---|---|
| `toybox` (594 888) | 239 063 / 0.13 / 0.01 | 227 874 / 0.44 / 0.01 | 225 444 / 1.17 / 0.01 | 225 416 / 2.89 / 0.01 |
| `app_process64` (51 856) | 5 203 / 0.01 / 0.00 | 5 149 / 0.04 / 0.00 | 5 126 / 0.11 / 0.00 | 5 115 / 0.25 / 0.00 |
| `libLLVM_android.so` (14 175 016) | 4 463 181 / 5.30 / 0.21 | 4 061 309 / 17.95 / 0.20 | 4 021 034 / 46.13 / 0.20 | 4 022 287 / 108.23 / 0.20 |

Распаковка плоская (~0.2 с на 14 МБ) на всех уровнях — работает только кодировщик.
L2→L3 на одиночных файлах это шум (±0.03%); брутфорс насыщается, остаточная
избыточность межфайловая.

### Малый смешанный сет (12 записей: 3 ELF, 2 скрипта, 1 rc, 1 prop + ссылка, 2 шрифта, 2 zip; 4 417 220 байт RAW)

| Уровень | Поштучные singles (сумма / enc) | Solid UCOMP02 (размер / enc) | Multi vs singles |
|---|---|---|---|
| L0 | 1 574 283 / 1.1 с | 1 498 130 / 1.3 с | 95.2% |
| L1 | 1 523 722 / 3.7 с | 1 475 667 / 5.0 с | 96.9% |
| L2 | 1 500 026 / 9.4 с | 1 485 905 / 9.3 с | 99.1% |
| L3 | 1 499 294 / 23.0 с | 1 475 653 / 13.6 с | 98.4% |

Round-trip multi проверен (`diff` + сравнение содержимого zip); распаковка multi ≈ 0.08 с.
На разнородных сетах общий словарь выигрывает на всех уровнях, а прогон
оптимизатора один вместо N.

### Полный ramdisk-сет (270 записей: 250 файлов + 20 zip со 156 inner; вход 94 604 983 байт)

| Метод | Размер | Доля | enc | dec |
|---|---|---|---|---|
| `gzip -9` tarball | 40 192 918 | 42.5% | 6.04 с | 0.25 с |
| Legacy C `lgz` поштучно + хранимые zip | 32 629 379 | 34.5% | н/д (пребилт) | ~2.1 с |
| Multi L0 | 26 172 615 | 27.7% | 40.3 с | 1.25 с |
| Multi L1 | 25 980 800 | 27.5% | 156.3 с | 1.27 с |
| Multi L2 | 25 980 723 | 27.5% | 290.8 с | 1.28 с |
| Multi L3 (словарь 64 МиБ, ZIP-инжест) | **25 016 070** | **26.4%** | 496 с | 1.23 с |

Сквозной итог: **130 898 200 → 25 016 070 = 5.23x**. L1≈L2 (разница 77 байт —
плато настоящее, L2 здесь ничего не дает); L0 уже бьет legacy C-покрытие на 20%.
Распаковка L3 lean-бинарником под `qemu-aarch64`: ~3.4 с, побайтово идентично.

### Чеклист валидации

* Полное дерево `cmp` чистое после каждой multi-распаковки (270/270 записей).
* Пересобранные zip проходят `unzip -t`; содержимое идентично ground truth
  (декодированному для ex-UCOMP); методы stored/deflated сохранены.
* Выходы хоста и `qemu-aarch64` побайтово идентичны; кросс-декод C↔Rust
  проверен в обе стороны на бинарниках, скриптах и шрифтах.
* Политика нулевых предупреждений (все 4 комбинации build/test ×
  default/no-default), `cargo test` зеленый (5/5 full, 4/4 lean).
